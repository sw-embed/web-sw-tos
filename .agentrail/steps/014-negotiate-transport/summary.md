Negotiated the framed transport: HELLO on startup with retry, TTY_OUTPUT routed by channel, CHANNEL_TITLE handled, unhandled frame kinds surfaced rather than dropped, input sent as TTY_INPUT on the focused channel once framed, transport mode in the status line. The bigger find was a one-byte bug: the SWTOS shell terminates commands on LF and Enter was sending CR, so help and ps -l parsed correctly and then answered BAD. With LF the full command set appears (help ls dir ps run df du mem stat uname) and ps -l returns the process table. This corrects a prediction I had written down and acted on -- I expected framing to unlock the shell, tested it, and found framed mode with CR still returned BAD.
